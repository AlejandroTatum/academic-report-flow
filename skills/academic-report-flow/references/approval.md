# Approval and format - Decision 2 (format before v1, no draft approval)

Phases `approval` (legacy, never waits) and `format`; the `typeset` phase that follows them is in `production.md`. There is no draft approval: once verify and format are `done`, the first formatted build is v1, generated with every rubric finding shown honestly, and generation is not a compliance claim. The human reviews the formatted version (`delivery.md`, Review), then asks for v2, v3 or gives an explicit instruction to publish; publication keeps its own gates (`delivery.md`, Deliver).

## Legacy approval phase

The route keeps the `approval` token so existing reports and status blocks still parse. No executor and no human gate run here: `doc_status` reports it `done` ("draft approval is not required; review the formatted report") and it never waits. An unmapped guide inventory item (`guide_inventory_unmapped`, `content.md`) is shown there as a finding: evidence coverage of the guide, never a score threshold; the publisher refuses while one stays unmapped.

A legacy `approval.yml` (`schema: academic.doc-approval/v1`, `body_sha256` of the exact `body.md` bytes, `approved_at`, `approved_by`, optional `typeset: required`) binds `body.md` to a past human decision. It is read as it stands, never migrated, repaired or deleted; a current or carried one keeps its own publication path (`APPROVAL_CURRENT`, `delivery.md`), and a stale one simply stops counting. Never record a new `approval.yml`: not to unblock a phase, a build or publication. Silence, an inferred yes, a restated plan or an agent decision never produces `approval.yml`. `approval_marker.py` with `--express` refuses: the express flow no longer records an automatic approval (`data.md`).

## Optional plain preview

When the user asks to read the plain text before v1, `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/draft_pdf.py" <folder>` builds `body.md` through the plain template (no cover, no logos, no course template, no validators) in a temporary directory outside the report and delivery folders, and `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/approval_packet.py" <folder> --open` prints the verify result, one summary row per criterion and the rubric trace with clickable `file://` links. Neither is a prerequisite for typeset or generate, neither binds anything, and the preview is never the final artifact.

## Format - before v1 (phase `format`, artifact `reports/<wf>/report.yml`)

Runs after verify and before `typeset`, so every format answer is in `report.yml` before v1 is built; it no longer rides on a draft-approval batch. Ask only the missing fields `doc_status` names and never re-ask what `report.yml` records, in ONE batch through `ask_user_choice` with suggested options, no free text: document format APE, AA, ACD or libre, plus Proyecto for a project report (`format_hint:` first when present), delivery format PDF or DOCX (`output:`), `format_spec` when `libre` is chosen (suggested options such as "documento sobrio sin portada" or "con portada"), and the metadata the chosen format still requires (subject, teacher, APE or ACD identification fields, group members). When the subject has a course repo (`~/Documents/Academicos/<subject-slug>/AGENTS.md`), the same batch confirms the delivery folder `unidad-<unit>/<practice_type>-<practice_number>-<topic>/` (the type is the course's own word, from `course_profile.py --check`) (suggest `metadata.unit`, `metadata.practice_number` and a short `metadata.topic` such as `actores-sdd`, read from the guide; `tema` is an alias of the title, never the topic). Never infer an answer and offer no default. Record each format answer in `report.yml` as soon as it is given, then run `tools/course_profile.py <folder>` so `delivery_dir:` is set before the final build. Format answers are plain `report.yml` data: a later request for content changes never reopens them, and later `delivery_dir`/`deliver_bibliography` edits do not stale the built PDF.

- One question for format selection through `ask_user_choice`: APE, AA, ACD or libre, plus Proyecto (hint first; the hint is not a choice, wait for the answer before recording `format:`). Metadata gaps are separate `ask_user_choice` prompts, never free text and never a second format-selection question.
- Delivery format PDF or DOCX is asked in the same format step, has no default, and is never inferred from the request or material; record it as `output:`.
- Delivery folder: with a course repo and no `delivery_dir:`, `doc_status` keeps format `pending` until the final build (a draft preview does not count); record `metadata.unit`, `metadata.practice_number` and `metadata.topic`, then run `tools/course_profile.py <folder>`. A delivery folder that holds anything besides `<slug>-vNNN.pdf`, its paired `.bib` and a `README.md` (the course-repo template ships one; it is allowed and delivery never touches it) keeps format `pending` with "delivery folder unusable" and the publisher's reason: ask the user to empty it or pick another `delivery_dir` now, before the build and the reviews, never after the final OK.
- AI declaration (part of every format; not a question to the user): `doc_status` keeps format `pending` naming `ai_declaration` until `report.yml` has it, so write it yourself, never ask whether to include it. Use `ai_declaration:` with `format: markdown` and `ai_declaration_position: after_bibliography`, and a `text:` with two tables: Tabla A, tools (tool | use), and Tabla B, prompts per iteration (the prompt verbatim when available; otherwise label the row explicitly as a summary, never invent a summary as if it were literal). It renders after the bibliography with the signature (PDF and DOCX). `ai_declaration: false` is the explicit opt-out and is written only when the user orders removing the declaration; with it no declaration renders and the phase is not blocked, but the LaTeX signature (single author or group grid) still closes the document. A report that already has a built, validated or reviewed PDF is never sent back to format for it.
- `ape`: practical-experimental technical report. Fixed sections: Objetivo(s), Materiales, Procedimiento (steps as a list), Resultados, Preguntas de Control, Conclusiones (tied to the objective), Recomendaciones, Bibliografía/Referencias (IEEE, or APA with `citation_style: apa`), Anexos. When the teacher says to leave a fixed section out, record its exact title under `ape_omit_sections:` and drop it from the body and the rubric; any other title is rejected. Extract its identification fields (cycle, unit, learning outcome, practice number and type, schedule, place, planned time) from the teacher's guide; the user only confirms or fills gaps. When `practice_type` is Grupal, record `metadata.members`.
- `aa`: academic activity report, rendered with `aa-report.tex` (editorial design; only page 1 is creative, with the letterhead, the left-margin identification ficha and the large serif title; pages 2+ are full width). Metadata: title, subject, teacher, student, date; optional `metadata.heading` replaces the large page-1 title, the PDF title and the running header (default "Aprendizaje autónomo"). Fixed sections, in order: Objetivo(s), Introducción, Desarrollo (free subsections), Conclusiones, Referencias (printed by the template; an authored heading is optional but must follow Conclusiones), Anexos (optional), Declaración de uso de IA (required: see the AI declaration bullet). `template: unl` keeps the old UNL look.
- `acd`: in-class session record (ACD), rendered with `acd-report.tex`. Its identification block reuses the APE keys: `title` is the session topic, `date` the session date and `practice_number` the ACD number, plus subject, teacher, student, cycle, unit, learning outcome, schedule, place and planned time; extract them from the teacher's guide like APE. Fixed sections, in order: Objetivo(s), Síntesis de contenidos abordados, Actividades desarrolladas en clase, Análisis / reflexión, Conclusiones, Referencias (printed by the template, as in AA), Anexos (optional). Markdown definition lists render as the label column of the record sheet.
- `ape`, `aa`, `proyecto` and `acd` have no cover by default; an explicit `cover:` in `report.yml` still wins. The fixed section lists of `ape`, `aa` and `acd` are applied in `body.typeset.md` (`typeset.py check`: `ape_structure`, `aa_structure`, `acd_structure`) and again by final validation; the plain draft is not checked against them.
- `libre`: wait for the user's own specification and record it verbatim as `format_spec:`; the plain template applies by default.
- Every format cites with IEEE by default; `citation_style: apa` is the opt-in when the guide demands APA, on any route; `ape`, `aa`, `proyecto` and `acd` map to the academic route, `libre` to the plain template. Missing metadata keeps the phase `pending`; an unrecognised value is `blocked`, never a silent fallback. Never fill identification fields on the user's behalf.

## Versions - literal edit orders (v2, v3)

Before v1 the agent may correct its own draft to satisfy findings (verify findings and the editorial pass, `content.md`), including adding required support; never invent evidence. Preserve user-authored wording and apply their explicit edit orders verbatim; ask before altering it or when a correction changes intended meaning, requires missing facts, or conflicts with instructions. Once a version is presented, do not silently change its prose: obtain the user's explicit edit order or consent to a proposed correction. Neither verifier findings nor a passing check are user consent. Apply the bounded-edit carry rules only after an authorized edit; they do not authorize one.

At review the user answers with literal edit orders ("in paragraph X replace '...' with '...'", "delete section Y", "move this paragraph before that one") or new evidence. Apply the user's text verbatim: never polish, rephrase or improve user-authored text; polishing forges authorship. Batch all literal edit orders from one reading into one round: apply them all verbatim in `body.md` and in `body.typeset.md`, re-verify, then build, validate and present the next version (v2, v3...) with a short list of what changed and the findings still open; never paste the whole body again for a localized change.

A bounded edit (at most 40 words inserted plus deleted, no Markdown heading added, removed or edited) keeps the verification, unless gaps were accepted (`production.md`, Verify), and the final review (`delivery.md`, Review); the body check, typeset bind, build and validation still run. An edit beyond the bound re-verifies with `--since verification.yml` (`production.md` step 5: only the criteria whose section changed go to the verifier) and re-read only what the edit touched. Incremental requirement verification re-checks changed criteria; the independent semantic review still examines the whole draft for cross-section repetition and gaps. The layout of every new version is audited again (`visual_pdf_auditor.py`, only the Changed pages, `production.md`). The loop repeats until the user gives an explicit instruction to publish.
