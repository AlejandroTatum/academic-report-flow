# Production - verify, generate, validate, quality gates

Tools enforce quality between the format decision and the review of each version: run each, report findings, never polish silently. Roots and interpreter: `routing.md`.

## Verify (artifact `reports/<wf>/content-check.yml`)

Runs after the draft passes the body check and before `format`, `typeset` and v1, so v1 is presented with the requirement matrix and its findings. No draft PDF has to exist first: when the user asks for the optional plain preview (`draft_pdf.py`, `approval.md`), start it in the same step as the verifier, because neither needs the other's output. Correct failures under the authorship policy in `approval.md`, in the same edit round as the editorial pass (`content.md`); ask for literal edit orders when user-authored text or intent is involved. A bounded edit (at most 40 changed words, no heading touched) keeps the verification: `content-check.yml` stays `pass` as long as every `found` quote is still in `body.md` and citations still resolve, so no verifier round runs. Larger edits re-verify with `--since` (`approval.md`, Versions).

1. `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/content_check.py" "$REPORT_CONTENT_ROOT/reports/<work-folder>/" --verify-brief`. Do not pass the drafting conversation to the verifier.
2. Give its exact output to ONE independent read-only verifier subagent. It never scores: it returns the requirement -> evidence matrix YAML the brief specifies (per rubric criterion, one or more `requirement` entries with `status: found|partial|missing`, `location`, and `evidence`, an exact quote from `body.md`, required when `found` or `partial`, plus a `gap` when `partial`; plus `unmapped_paragraphs` and `findings`). Evidence it cannot quote is `missing`, never "seems to comply". Launch it with `Risk: item 6 (no automated test catches a requirement missing from the prose)` in its launch context: the Gentle runtime admits an independent verifier only with a declared risk item, and this one is genuine. A refused launch is a routing error to correct in place, never a reason to pause the report or hand the verifier to another session or to the user.
3. Save the YAML unchanged as `verification.yml`; the drafting agent never writes verification.yml. Run `content_check.py <folder> --verification verification.yml`.
4. The tool validates the file; a `found` or `partial` requirement whose exact quote is not in `body.md` (whitespace-normalized) is downgraded to `missing` with a finding; a criterion is `cumple` when all its requirements are found, `falta` otherwise (a `partial` requirement keeps it `falta` and its `gap` is shown in the v1 findings). It adds the mechanical checks (citations resolve; at least 5, or the report's `min_sources:`, eligible sources cited, or with `uncited_bibliography: true` at least 1 bib entry and no citation required; `links_resolve`: every http(s) URL in the body is opened, an HTTP error fails, a timeout or DNS failure only warns) and writes `content-check.yml` bound by hash to body, rubric, bib and guide. A stale marker means re-run the verifier on current inputs; a verification is reused only when the body change is markup-only (same `body_text_sha256`, same rubric). Legacy markers with `judges:` stay valid.
5. Re-verify after an edit that is not bounded (a bounded edit keeps the marker, `content-check.yml` reads it against `checked-body.md`): run step 1 with `--since verification.yml` (the previous file). The brief lists only the criteria whose mapped section changed for re-check; the verifier returns requirements for those criteria only (an empty list when none changed). Step 3 merges the carried-over requirements itself from the previous `content-check.yml` (same rubric, same section hash, criterion absent from the answer) and re-checks their quotes against `body.md`; the marker lists them under `carried_criteria`. A rubric change forces a full verify. Then continue with steps 2-4 as usual.
6. Accepted partials (human only). When the check fails only on `partial` requirements and the user decides to accept one, run `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/accepted_gaps.py" accept <folder> --by "<their name>" --requirement "<exact requirement text>" --reason "<their reason>"` (repeat the `--requirement`/`--reason` pair per gap; `--criterion <id>` if the text repeats). Only after they name the requirement and the reason in the conversation; never suggest or invent either, never write `accepted-gaps.yml` by hand. It refuses a requirement that is not `partial` by exact text (`missing` is never accepted), a blank name or reason, and a `content-check.yml` that is absent, stale or malformed. The file binds body, rubric, bib and the recorded requirements: any edit or re-verify that changes them makes it stale and the gap is an open finding again, refused by the publisher, until the person accepts anew. `content-check.yml` and `rubric-grade.md` are untouched; mechanical failures are never waived. `doc_status` then reports verify `done` with the accepted-gap count, and the publisher no longer refuses that requirement.

When the executor cannot launch subagents, it stops at verify and reports the verifier pending; the orchestrator runs the verifier exactly as above (brief verbatim, one independent read-only subagent, YAML saved unchanged) and the executor never stands in for the verifier.

The check only reports (per-criterion `cumple|falta`, the requirement matrix with missing items, citation and link problems, unmapped paragraphs as deletion candidates). It never rewrites `body.md`; never add requirements for criteria the plan does not name. The independent verifier also reviews the whole draft for semantic repetition, circular explanations, ambiguity and missing context, reporting specific locations and suggested corrections in findings, including during incremental verification. Mechanical length and filler checks cannot establish semantic concision; findings are advisory, not scores. Report every finding verbatim; use the correction policy and literal edit orders (`approval.md`) to preserve authorship. Deletion candidates are suggestions, not automatic removals. A recorded `fail` made only of rubric findings (`missing` or `partial` requirements, `rubric_checks`, `eligible_sources_cited`) leaves verify `done` with "rubric findings (not a compliance pass)": v1 is generated with them, never a compliance claim, and the publisher refuses them until they are fixed or, for a `partial`, accepted. A technical failure (an unresolved citation, a broken link, a `body_format:` problem) blocks the route (`content_check_failed`) until fixed; an edited draft stales the marker and reruns the check, except a bounded edit (no accepted gaps), which keeps it. Fix advisory findings in the same edit round as everything else; on their own they never justify another verifier round.

## Typeset (artifact `reports/<wf>/body.typeset.md`, bound by `typeset.yml`)

Runs after `format`, before generate: `body.md` is plain text, so backend formatting is applied only in its copy and never invalidates verified content. Binding asserts no approval.

One command runs the whole build phase: `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/build.py" "$REPORT_CONTENT_ROOT/reports/<work-folder>/"` runs the same code as `typeset.py auto` (step 1 below, with its `left for you:` and check lines) and, only when every typeset check passes, the same code as `build_report_auto.py` (Generate), with the same messages, refusals and exit status. While the bind is refused or a check fails it builds nothing: finish `body.typeset.md` (steps 2-4) and run the same command again. A report that does not use typeset (legacy, below) skips step 1. After a successful build it prints what the validate phase still needs (inspect every page of the final PDF, record `validation.yml`); it never writes `validation.yml`, `approval.yml`, `final-review.yml` or `body.md`, offers no option that skips a gate, and records the existing `typeset` and `generate` timings. `typeset.py auto|bind|check` and `build_report_auto.py` keep working on their own.

1. `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/typeset.py" auto "$REPORT_CONTENT_ROOT/reports/<work-folder>/"` copies `body.md` to `body.typeset.md` when missing and writes `typeset.yml` with the `body.md` sha256, plus a `typeset-source.md` snapshot of the bound `body.md`. It needs no draft approval. While `body.typeset.md` is still that untouched copy, `auto` then formats what needs no judgement: runs of two or more `- a; b; c` lines with the same three or more cells become a table (empty header row, numeric columns right-aligned), `Figura: caption (path.png)` lines become `![caption](path.png)` and bare URLs become `<url>`. It prints `left for you:` lines for what it did not decide (tables without column names, two-cell `- a; b` runs, possible formulas) and never rewrites a typeset body that already differs from `body.md`. `typeset.py bind` only copies and binds.
2. Finish `body.typeset.md` by hand, starting with the `left for you:` lines: name the columns of every table, formulas as math, any data `auto` left as a list as tables, `Figura: caption (path.png)` lines as `![caption](path.png)` (append `{width=70%}` and/or `{height=50%}` to size that one figure; without it the default sizing applies), bare URLs as links, the format's fixed headings. Keep every word and `[@key]` of `body.md`; never touch `body.md`.
3. `typeset.py check <folder>` passes only when the binding matches the current `body.md`, the typeset body passes the format check (level-1 headings, no Unicode sub/superscripts, no bold pseudo-headings), every table names its columns (`table_headers`) and the format's fixed headings, and it cites exactly the same `[@key]` set as `body.md`. Run it until it passes (`doc_status` shows `typeset: done`).
4. Any edit of `body.md` after a bind stales the binding: apply the same edit in `body.typeset.md`, then bind again. The re-bind refuses, writing nothing, while a word the edit inserted is missing from `body.typeset.md` or the text it removed is still there (`missing: «...»`, `still present: «...»`).

Legacy: an `approval.yml` without `typeset: required` predates this phase; its report needs no typeset (`done`) and `body.md` renders as before. A typeset body bound on a legacy report is rendered, so it must pass the same checks before the final build. Both tools exit non-zero on failure and print the finding.

## Generate (artifact: the final PDF under `outputs/<materia>/`)

Runs once `verify`, `format` and `typeset` are `done`; no draft approval is needed and rubric findings never stop it. The final build prints `TYPESET REQUIRED` while a required typeset is not current. A rubric check that already fails in `body.md` is printed under `RUBRIC FINDINGS (no es una declaración de cumplimiento; bloquean la publicación)` and v1 is still written; the build then ends with `PDF GENERADO CON HALLAZGOS DE RÚBRICA (no validado para publicar)` instead of `PDF GENERADO Y VALIDADO`; present those findings with v1, never as met. A check lost in typeset or in the PDF, and every other validation error, still fails the build. A successful PDF build writes `build/generation.yml`, binding the PDF bytes to the current `body.md`, rendered body, bibliography and render settings; the publisher needs it current (`delivery.md`). The optional plain preview (`draft_pdf.py`, `approval.md`) is review-only, never the final artifact.

`build.py` (Typeset) runs this step after typeset passes; on its own, `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/build_report_auto.py" "$REPORT_CONTENT_ROOT/reports/<work-folder>/"` builds from `report.yml` (including `format:`) plus `body.typeset.md` while its binding is current (otherwise `body.md`), runs the configured technical validation, and reports the artifact hash and page count. A final PDF older than `body.typeset.md` is stale (generate pending). It does not publish, copy or version, and never writes `approval.yml` or claims `VISUAL_PASS`, `HUMAN_REVIEW` or `READY_TO_SUBMIT`. Final PDF/DOCX stay under `outputs/<materia-slug>/`, intermediates in `build/` or `backups/`.

Optional `figure_placement: here` in `report.yml` pins every figure where it appears in `body.md` (LaTeX `[H]`) instead of letting it float to the end of its section or subsection (a figure never crosses the next heading of either level); the default `float` keeps today's output, and any other value is rejected.

## Validate (`next: validate`, artifact `reports/<wf>/validation.yml`)

Receipt schema `academic.doc-validation/v1`: `artifact_sha256`, `result: pass|fail`, `mode: fallback`, `gates`, `recorded_at`, `evidence`, optional `reason`, and `bibliography_sha256` only when `report.yml` sets `deliver_bibliography: true`. There is no production writer: the executor records the hashes. Done = `result: pass` and `artifact_sha256` matches the current PDF; `fail` is `blocked` (`validation_failed`); a missing receipt or stale hash stays `pending`.

When `deliver_bibliography: true`, the receipt also records the exact SHA-256 of the declared `.bib`, written only after the applicable checks pass; missing, malformed or stale keeps validate pending and delivery refuses.

Document validation never uses RDD: the work folder lives in the content root, outside the session's repository, so a native review would always stop to ask. Run the chain below regardless of the global review switch, without probing it and without asking; RDD stays for code changes in the automation repository. Older receipts may still say `mode: rdd`; they are read like any other receipt.

Chain (`mode: fallback`, `evidence: backups/quality_report.md`), in order:
1. `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/validate_report.py" "$REPORT_CONTENT_ROOT/reports/<work-folder>/"`: `common` is mandatory and PDF output also needs `pdf_layout` (only `--tex-only` skips it). Its `rubric` check (only with a `rubric.yml`) re-runs every rubric check on the body the build rendered (`body.typeset.md` while bound) and on the PDF text; a check that passes on `body.md` but fails there was lost in typeset, and checked text or headings missing from the PDF text were lost in the build. Each is a validation error; evidence quotes missing from `body.typeset.md` only warn (`rubric_trace.py <folder> --body body.typeset.md --pdf <final-pdf>` shows the same losses). A report without `rubric.yml` is not checked; there is no score threshold. `validate_report.py` still fails on the rubric findings v1 generation printed: record the receipt as it is (`result: fail`, the findings in `reason`) and present v1 for review with them anyway (`delivery.md`, Review); the receipt passes, and publication opens, only once a later version fixes them. While `build/generation.yml` is current for that PDF, `doc_status` keeps validate `blocked` (`validation_failed`) and routes `next: review` with review `current - v1 failed validation: review it and request a revision (v2/v3); publication stays blocked`: show v1 with its findings and ask for the revision; a final review recorded then never opens delivery (deliver stays `pending`).
2. `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/visual_pdf_auditor.py" "$REPORT_CONTENT_ROOT/outputs/<materia-slug>/<final-pdf>.pdf"`: report and `contact_sheet.png` are `AUDITOR_PRECHECK` evidence only (manual unless `validators: {visual_pdf: true}`).
3. Rendered readback and semantic inspection: headings, paragraphs, captions, bibliography, tables and figure labels present, legible and equivalent to the source.

After the chain passes, run `"$REPORT_PYTHON" "$REPORT_AUTOMATION_ROOT/tools/rubric_grade.py" "$REPORT_CONTENT_ROOT/reports/<work-folder>/"` on the final PDF: it writes `rubric-grade.md` and `rubric-grade.yml` in the work folder (`delivery.md`, Review). The verifier never scores; only this tool computes the estimate.

Gates: `BUILD_PASS`, `VALIDATION_PASS`, `VISUAL_PASS`, `HUMAN_REVIEW`, `READY_TO_SUBMIT`; the chain never lowers, skips or renames one, or grants one it did not verify on the same immutable artifact. Validation is not approval.

| Gate | Proof |
|---|---|
| `APPROVAL_CURRENT` | legacy reports only: `approval.yml` current for the exact `body.md` bytes; a v1 report has none |
| `BUILD_PASS` / `VALIDATION_PASS` | build completed / validators pass (layout still unproven) |
| `VERSIONED_PDF_PUBLISHED_OR_REUSED` | precondition `APPROVAL_CURRENT` (legacy) or a current `build/generation.yml` plus a passing content check; PDF-only version published or hash-reused; not approval |
| `VISUAL_PASS` | readback plus direct page inspection pass on one immutable artifact |
| `HUMAN_REVIEW` | `final-review.yml` for the same bytes |
| `READY_TO_SUBMIT` | every previous gate passes, artifacts unchanged |

`VISUAL_PASS` ownership: the validate phase executor that performed the direct page-by-page inspection (every page rendered and read back, or after a correction the pages `visual_qa.md` lists as changed, no blocking defect) records `VISUAL_PASS` in `validation.yml` `gates:` and notes it in the evidence report; a receipt without an inspection never records `VISUAL_PASS`. `READY_TO_SUBMIT` follows once `HUMAN_REVIEW` exists for the same bytes (`deliver_report.py` derives it).  Never write `approval.yml`, `body.md` or `report.yml` here.

## Quality gates (inspection a tool cannot do)

Visible evidence overrides automation: a visible blocking defect fails the artifact even when every script passes. Record the artifact hash and page count first; inspect every contact-sheet page and open every page with diagrams, figures, captions or tables at readable size. Batch every visible correction first, then rebuild the whole artifact once and rerun every tool on it; never rebuild per fix; explain material page-count changes. The auditor compares rendered pixels with its previous run in the same output folder (`page_hashes.json`): `visual_qa.md` lists the **Changed pages** and `changed_contact_sheet.png` shows them. Inspect only those pages again; a pixel-identical page keeps its earlier verdict. A first audit, a DPI change or `Changed pages: first audit` means inspect every page.

Blocking defects:
- Academic route only: cover on page 1, body from page 2, UNL logo present.
- Headings without substantial following content (orphan heading: after a heading the same page must fit two lines of body text, a table header plus one data row, or a complete figure); clipped images, overfull boxes, accidental blank pages, pages under 20% meaningful content, half-empty pages from table pagination. `visual_pdf_auditor.py` only warns on orphans; inspect before deciding.
- Whitespace: over 40% of the lower page empty without a natural section close. An intentional gap or natural close is approvable only with a recorded visual justification; page-break space, an unsplit table or a page holding an isolated title is a defect. Record every page under 20% content, over 40% lower empty, heading before a page break, or whole table displaced.
- Tables render as real grids (visible rules, distinct header, legible type; never raw Markdown pipes). Remove unneeded columns before compressing; split wide tables (e.g. `Code | Actor | Requirement | Priority` and `Code | Acceptance criterion`). Broken tables repeat the header. With `table_styles: {enabled: true}` every table needs a `<!-- table-style: <key> purpose=... -->` directive; run `tools/check_table_contexts.py <dir>`. The catalog (`templates/table_styles.yml`) also has the institutional style `TAB-IN-08` ("Institucional UNL": UNL-blue `#1F5F8B` header with white bold text, soft alternating rows, left-aligned). It is never chosen automatically; request it per table with `table_styles: {overrides: {<table_key>: TAB-IN-08}}` in `report.yml` (or as the institution default under `tables.institution_override`).
- Type shrunk to fit is a defect; a table that cannot split is a defect unless a split was attempted.
- Figures: lower border clears the footer, terminal nodes complete, no clipped or overlapped node or connector, full caption attached to the right asset. Each diagram models its module's real decisions and visually differentiates user, system, internal module, external service, validation, error, retry and final state. Diagrams that only restate the text, clipped terminal nodes and captions detached from their figure are defects. Reject repeated templates, generic decisions such as `¿Validación correcta?`, flows with no real alternatives, ambiguous arrows.
- Practice reports keep each exercise self-contained (data first, process and evidence after); conclusions never open with formulaic `Se concluye`; validate the rendered bibliography (IEEE, or APA with `citation_style: apa`), not only the `.bib`.
